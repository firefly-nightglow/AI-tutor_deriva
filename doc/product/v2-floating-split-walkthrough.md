## 自动检查

受测系统为 Windows，Electron 实际版本 39.8.10，显示缩放 150%，工作区 1707×1019 DIP。系统边界的物理像素换算允许相邻 1 DIP 舍入，但持久化的用户逻辑宽度必须精确保留。

- `npm test`：50 个测试文件、251 项测试通过，包含新增的高 DPI 宽度累计回归。
- `npm run build`：主进程和渲染进程类型检查、生产构建通过。
- `scripts/floating-split-smoke.ts`：在独立用户目录运行实际构建；exercise、restore、invalid 三个阶段分别验证流式并存、正常恢复和非法状态恢复。移动结束通知是模拟事件，不能作为真实标题栏拖拽证据。
- `scripts/material-app-smoke.ts`：实际 preload、内部资料来源、普通/悬浮截图确认预览、模态遮挡及恢复、本地模拟图片 API、附件读取与书签；只有退出码为 0 且存在完整 PASS 标记才算有效通过。
- 图片跨进程恢复测试使用合成 JPEG；真实图片捕获和发送由上一个脚本覆盖。所有模型请求都指向本机临时服务，不使用真实 Key、不产生模型费用。
- 测试配置、SQLite、图片与结果保存在被忽略的 `node_modules/.cache/`；不修改用户学习记录。

本轮正式重复执行 `node scripts/run-window-acceptance.cjs --runs=10`，得到 exercise/restore/invalid/material 各 10 次通过，共 40 个有效结果、0 失败。核验方式：读取 `results.json`，按 phase 分组，并要求每条 pass=true、exitCode=0 且能定位同编号日志中的完成标记；未发现辅助进程或缺少日志的误计项。早期中止或调试中的运行不纳入这组分布。本机 readyMs 为 355–1126ms，modeSwitchMs 为 9–25ms。

### 重跑方式

先执行 `npm run build`，再分别构建测试驱动：

```powershell
.\node_modules\.bin\esbuild.cmd scripts/floating-split-smoke.ts --bundle --platform=node --external:electron --format=cjs --outfile=out/main/floating-split-smoke.cjs
.\node_modules\.bin\esbuild.cmd scripts/material-app-smoke.ts --bundle --platform=node --external:electron --format=cjs --outfile=out/main/material-app-smoke.cjs
```

按顺序执行以下命令；每一条都应输出 PASS，否则保留失败而非继续判为通过。同一隔离配置不可并发运行：

```powershell
.\node_modules\.bin\electron.cmd out/main/floating-split-smoke.cjs --phase=exercise
.\node_modules\.bin\electron.cmd out/main/floating-split-smoke.cjs --phase=restore
.\node_modules\.bin\electron.cmd out/main/floating-split-smoke.cjs --phase=invalid
.\node_modules\.bin\electron.cmd out/main/material-app-smoke.cjs
```

也可在构建两个驱动后执行 `node scripts/run-window-acceptance.cjs --runs=10`。它以正常 GUI 显示条件顺序启动四个阶段，逐次要求退出码为 0 且包含 PASS；遇到失败立即停止。结果位于 `node_modules/.cache/deriva-window-acceptance/results.json`，日志与结果行一一对应，不把辅助进程或缺少完成标记的启动计为成功。

运行时输出 `readyMs` 是从驱动装载后到 React/preload 就绪且主窗口可见的耗时，不包含操作系统启动 Electron 的全部成本；`modeSwitchMs` 是桥接调用到相应 DOM 布局状态的观测，不等于视频播放或拖动帧率。规格没有给定毫秒阈值，本表不另造发布门槛。
