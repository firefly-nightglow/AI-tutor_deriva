# PRD - Deriva 桌面学习助手

Status: draft
Created: 2026-10-02
Updated: 2026-10-02
Owner: 产品所有者（本人）

## Product

Deriva 是一个常驻桌面的 AI 学习助手，为自学课外资料的大学生提供不打断学习流的提问入口、按逻辑关系组织的树状对话、以及基于学生已有知识水平作答的教学辅导。名称取自 derivation：知识从主干推导、衍生出枝杈，对应树状对话的核心形态。

## Target User

大学本科生，尤其是围绕课外高质量资料（经典教材、公开课）进行大量自主学习的学生。首要用户与首要验收者是产品所有者本人（大一新生，自学场景包括 Gilbert Strang《线性代数与数据学习》、数列极限等数学内容）；只有首要用户真实每日使用并认可后，才考虑推广给同类学生。

## Problem

今天，这类学生在自学时必须频繁打断学习流：遇到教材引用的陌生定理或概念，要切到浏览器查资料或打开网页版 AI 提问，再切回来，学习积极性被反复消磨。现状的代价体现在四个方面：

1. **学习流被打断**：查资料的动作繁琐，每次切换都是一次注意力税。
2. **AI 回答错位**：通用 AI 常从二级结论或超出学生知识储备的内容（如对未学积分的学生用斯特林公式）出发作答，旧疑惑未解又添新疑惑，学生要反复细化提示词才能得到能看懂的回答——根因是 AI 与学生对"当前学到哪里"的信息高度不统一。
3. **逻辑关系丢失**：追问（如"这段推导里引用的定理是怎么来的"）与原回答是包含/分支关系，但对话界面按时间线性排列，轮数一多，学生无法把握内容间的逻辑结构，也难以高效整理。
4. **缺乏掌握度检验**：自学大量新知识时，学生没有有效手段构建知识点之间的联系，也没有办法检验自己是真懂还是"看答案时觉得懂"。

如果本产品不存在，用户将继续忍受"浏览器 + 网页版 AI + 手工整理笔记"的割裂流程，上述四类损耗每天重复发生。

## Goals

- 学生在阅读或观看学习资料时，不离开当前窗口即可发起一次有完整学习上下文的提问（悬浮窗随手可达）。
- 针对 AI 输出内容的追问以子对话形式挂在被选内容下，学生能在任意时刻看清一次学习中"问题 - 追问 - 追问的追问"的完整逻辑结构。
- AI 的回答从学生声明/记录的知识水平出发，不引入学生未掌握的前置知识；若必须引入，先解释该前置知识本身。
- 对话数据完全本地保存，重启不丢失，可跨天、跨周回溯任意一次学习问答。
- 结束一段学习后，学生能获得结构化总结与针对性的掌握度检验（v3 目标）。

## Non-goals

- 嵌入或逆向使用 DeepSeek 网页版（ADR-0002：API-only）。
- Android / iPad 原生应用（ADR-0001：Windows 桌面优先；架构预留平台无关核心模块）。
- 外部数据库、云同步、多设备同步（SQLite 本地存储，数据完全私有）。
- 多用户、账号体系、社交或班级协作功能。
- 通用聊天机器人定位——产品是学习辅助工具，不追求替代通用 AI 对话产品。
- 替你学习：产品辅助理解与检验，不生成"应付作业式"的完整答案流。

## Success Metrics

- v1 验收：能创建至少 3 层嵌套子对话；能同时查看主对话与子对话并自由选择开关任意层级；对话数据本地保存、重启不丢；树状对话全部子功能（选中开子对话、对话书签、树状侧栏、单对话链路图、按科目分类存档）正常；模型调用走用户 API key 且教学系统提示词初版上线 — 测量来源：v1 功能规格验收清单。
- 首要用户每日自学中真实使用：连续 2 周内，每次自学会话中的提问经由本产品完成而非切到浏览器/网页版 AI — 测量来源：首要用户自评 + 本地对话记录时间分布。
- "从底层知识作答"达标率：首要用户主观判定 AI 回答未引入未掌握前置知识的比例超过 80% — 测量来源：黄金对话集回归评估（v2 起）。
- 长对话可导航性：超过 20 轮的对话树中，定位任意历史内容不超过 2 次点击（书签/链路图/树状侧栏）— 测量来源：v1 功能规格验收。

## Roadmap

- **MVP tier** - 悬浮窗（边缘吸附、分屏、全局热键）- 学习资料旁的随手提问入口，不打断学习流。
- **MVP tier** - 树状对话（主/子/子子对话、选中 AI 输出开子对话、对话书签、树状侧栏与单对话链路图、按科目分类的多对话存档）- 保留问题间的逻辑结构，长对话可导航、可整理。
- **MVP tier** - API 对话（DeepSeek 官方 API，OpenAI 兼容适配层，key 仅存本地）+ 教学系统提示词初版（最近发展区约束、从学生知识水平出发、回答带出处）- 回答贴合学生当前水平。
- **Next tier** - 屏幕感知（截图提问、选中即问，基于 deepseek-flash 视觉能力）- AI 与学生共享"当前在看什么"的信息，消除上下文错位。
- **Next tier** - 提示词版本化 + 黄金对话测试集 - 教学提示词可按真实使用案例迭代改进。
- **Later tier** - 学习会话（开始/暂停/结束学习、纪要模板总结、Markdown 思维导图）- 一段学习结束后的结构化沉淀。
- **Later tier** - 出题检验 + 费曼模式 + 知识画像 - 基于提取练习与间隔重复的掌握度检验，AI 回答随学生水平持续对齐。
- **Later tier** - 导出 Markdown（对话树、思维导图至 Obsidian）- 学习成果不被锁死在应用内。

## Constraints

- Technical: Windows 桌面应用（Electron + React + TypeScript），SQLite 本地存储，不接外部数据库（ADR-0001）。
- Technical: 模型接入仅走用户自备 API key（默认 deepseek-flash，OpenAI 兼容适配层），key 仅本地保存（ADR-0002）。
- Business: 模型调用成本由用户自付，产品须在 UI 中展示 token 用量与估算花费，保持成本透明。
- Delivery: 按 MVP / Next / Later 三期交付，各期边界见 ADR-0003。

## Open Questions

- 科目之下是否需要标签系统（二级分类）？— 推迟：待 v1 实际使用后按真实分类需求决定，避免过度设计。
- 是否引入"文本对话走 deepseek-v4-pro、截图理解走 deepseek-flash"的双模型路由？— 推迟：v2 屏幕感知上线后按回答质量与成本评估，若引入则形成新 ADR。
- 全局链路图（跨主对话）的节点与连边如何定义？— 推迟：依赖 v3 知识点提取能力，届时以概念节点设计为准。
- Android / iPad 移植是否启动？— 推迟：仅当 Windows 版被首要用户及同类学生验证后考虑；架构已预留平台无关核心模块。
