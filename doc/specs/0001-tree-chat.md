# Spec 0001: 树状对话（Tree Chat）

**Status:** `accepted`
**Created:** `2026-10-02`
**Owner:** `产品所有者（本人）`

## Context

通用 AI 对话产品按时间线性排列问答，学生针对 AI 输出内容的追问（"这段推导引用的定理是怎么来的"）与原回答之间是包含/分支关系，却被排成上下结构；轮数一多，逻辑关系丢失、上下文难以回看、知识无法整理。这是 PRD 定义的痛点 3，也是本产品区别于市面套壳聊天框的核心差异化功能（ADR-0003 将之列于 MVP tier 首位）。本功能同时为痛点 1 服务：树状对话运行在即问即答的桌面对话界面内，是后续悬浮窗形态的承载体。若本功能不交付，产品退化为又一个线性聊天框，失去存在意义。

术语沿用 CONTEXT.md：主对话、子对话、对话书签、科目。

## User Scenarios

- **Scenario 1:** 发起主对话并连续问答
  - Given 用户已配置 API key，且选中了某个科目（或默认"未分类"）
  - When 用户新建主对话并输入问题发送
  - Then AI 流式输出回答，公式以 KaTeX 渲染，整轮问答即时持久化，界面显示所用模型标识

- **Scenario 2:** 选中 AI 输出内容发起子对话
  - Given 主对话中已有一段 AI 输出
  - When 用户用光标或触屏选中其中一段文本（公式、定理名、推导步骤），点击浮出的"追问"入口并输入问题
  - Then 系统创建该主对话的子对话，被选内容作为引用显示在子对话顶部并随提问一同发给模型；子对话出现在树状侧栏对应节点下

- **Scenario 3:** 多层嵌套追问
  - Given 已存在一个子对话
  - When 用户在该子对话的 AI 输出中再次选中文本追问
  - Then 生成下一层子对话，嵌套层数无硬性上限，至少 5 层内全部功能（侧栏、书签、链路图、多栏查看）正常

- **Scenario 4:** 多栏对照查看
  - Given 存在主对话与多个子孙对话
  - When 用户从树状侧栏或链路图中打开主对话与任意子孙对话
  - Then 各对话以并列面板同时显示，用户可独立滚动任一面板、关闭任一面板，且可随时再打开

- **Scenario 5:** 书签跳转
  - Given 某个对话内 AI 已输出多段回答
  - When 用户点击面板边缘竖直排列的某枚对话书签
  - Then 面板滚动定位到该书签对应的输出段落并将其高亮

- **Scenario 6:** 链路图查看
  - Given 一个含有多层子对话的主对话
  - When 用户切换到链路图视图
  - Then 看到以该主对话为根、子对话为分支节点的关系图；点击任一节点跳转到对应对话内容

- **Scenario 7:** 对话归档与回溯
  - Given 用户历史上创建过多个主对话，分属不同科目
  - When 用户重启应用后查看左侧列表
  - Then 全部主对话按科目分组、组内按时间排序完整呈现，数据无任何丢失

## Requirements

### Functional

- FR-1: 用户可创建、重命名、删除科目；主对话创建时归属当前选中科目，未选择时归入"未分类"；主对话可改挂到其他科目。
- FR-2: 主对话内支持连续多轮问答，AI 回答流式输出，Markdown 与 KaTeX 公式正确渲染，每条消息记录并显示所用模型名。
- FR-3: 用户选中任意一段 AI 输出文本后，出现"追问"入口；确认后创建子对话，被选片段作为引用块置顶显示，并作为上下文随该子对话的提问发送给模型。
- FR-4: 子对话支持无限层级嵌套（子子对话），创建方式与 FR-3 一致；至少 5 层深度内无功能降级。
- FR-5: 树状侧栏完整展示当前主对话的对话树，节点可展开/折叠，点击节点定位或打开对应对话面板，当前查看中的节点有视觉标记。
- FR-6: 对话内每段 AI 输出自动生成一枚对话书签，竖直排列于该对话面板边缘；点击书签滚动定位到对应段落并高亮。
- FR-7: 用户可在"对话视图 / 链路图视图"间切换；链路图以当前主对话为根渲染整棵对话树，节点显示对话标题摘要，点击节点跳转对应内容。
- FR-8: 用户可同时打开主对话与任意多个子孙对话面板并列对照，每个面板可独立关闭、独立滚动；面板数量超出可视宽度时横向排布规则见 FR-15。
- FR-9: 全部对话数据（科目、对话树、消息、书签、引用关系）即时写入本地 SQLite；流式输出中途断开时，已收到的部分照样保存。
- FR-10: 主对话与子对话标题自动生成（取首条提问的摘要）且可随时手动重命名。
- FR-11: 删除对话节点时若其存在子孙对话，须提示受影响的子孙数量并要求二次确认；确认后级联删除整棵子树。
- FR-12: 对话标题允许重名（以科目 + 时间 + 树内位置区分）；科目名不允许重名，重名创建时给出提示。
- FR-13: 切换默认模型后，历史消息保留各自原模型标识，新消息使用新模型标识；旧对话不做任何回溯性修改。
- FR-14: 空输入（纯空白字符）不可发送；发送中禁止重复提交同一问题。
- FR-15: 并列对照面板默认最多平铺 3 栏，超出后该区域可横向滚动；每个面板有明确的关闭控件与所属层级标识（如"主对话 / 子对话 L2"）。
- FR-16: 对话书签摘要（FR-6）与对话标题（FR-10）的自动生成方式提供用户设置项："本地截取首句"（零额外 token 消耗）或"模型生成摘要"（设置界面须明确提示会产生额外 token 消费）；默认值为"本地截取首句"。手动重命名功能不受该设置影响。

### Non-functional

- NFR-1: 本地存储使用 SQLite（better-sqlite3），无任何外部数据库依赖；单次消息写入在普通笔记本上不超过 50ms。
- NFR-2: API key 使用 Electron safeStorage 加密后存于本地，不以明文落盘，不写入任何日志文件，不随诊断信息外发，仅发送至 api.deepseek.com。
- NFR-3: 错误处理：API 请求失败、网络超时（30 秒无响应）时，对应消息进入错误状态并提供重试按钮，已流式收到的内容保留不丢；对鉴权失败、余额不足、限流分别给出可理解的提示文案。
- NFR-4: 性能：含 1000 条消息的对话树从点击到可交互不超过 500ms；链路图在 300 节点内渲染与缩放流畅，超出时按子树懒加载；流式输出期间界面保持 60fps 滚动。
- NFR-5: 触控适配：选中文本、追问入口、面板关闭控件在 Windows 触屏设备上可用，点击热区不小于 44px。

## Success Criteria

- 可创建至少 3 层嵌套子对话（主对话 → 子对话 → 子子对话），且每一层均可正常问答、回看。
- 可同时查看主对话与任一子孙对话，且用户能自由打开或关闭任意层级的面板。
- 对话数据本地保存，应用重启后完整恢复，无消息丢失。
- FR-3、FR-5、FR-6、FR-7、FR-9 全部通过各自场景的手动验收。
- 模型调用全程走用户自备 API key；教学系统提示词初版（最近发展区约束 + 回答带出处）作为 system prompt 生效。
- 超过 20 轮的对话树中，定位任意历史内容不超过 2 次点击（书签、链路图或树状侧栏）。

## Edge Cases

- 空状态：无任何主对话时，列表区显示引导创建文案与入口；无科目时自动提供"未分类"；对话内尚无 AI 输出时书签栏为空且不占位。
- 深层嵌套：树状侧栏缩进在第 5 层后封顶，更深层级以层级角标（如 L6）标识；链路图节点过多时支持缩放与拖动平移。
- 删除有子节点的对话：按 FR-11 二次确认并级联删除；删除当前正在查看的对话时，其面板关闭并回到父对话。
- 重名：对话标题允许重名；科目重名被拒绝并提示。
- 切换模型：历史消息保留原模型标识（FR-13），链路图与侧栏不受模型切换影响。
- 选中内容跨多个段落或包含公式时，引用块保留原始 Markdown/LaTeX 源码。
- 应用异常退出（崩溃、断电）后重启，最后一条流式消息保留已收到的部分。

## Out of Scope

- 屏幕捕获、截图提问、选中屏幕内容提问（v2，见 ADR-0003）。
- 视频字幕提取、纪要模板总结、思维导图、自动出题、费曼模式、知识画像（v3）。
- 全局（跨主对话）链路图（待 v3 知识点提取后定义，见 PRD Open Questions）。
- 对话内容搜索、标签系统（推迟决策，见 PRD Open Questions）。
- 云同步、多设备、多用户、对话分享与协作。
- 悬浮窗形态本身（边缘吸附、分屏、全局热键）——独立规格另行编写，本规格只覆盖对话功能在普通窗口内的行为。

## Open Questions

- OQ-1: 对话书签的摘要文案如何生成？方案 A：本地截取该段输出首句（零额外成本）；方案 B：调用模型生成一句话摘要（每段输出多一次 API 调用，成本略增但摘要质量高）。倾向 A，待确认。

  决议（2026-10-02）：做成用户设置项，A/B 均可选并提示 B 的额外 token 消费，默认 A。已落入 FR-16。
- OQ-2: 子对话提问时携带的上下文范围？方案 A：仅被选片段 + 用户问题；方案 B：被选片段 + 从根到该节点的完整对话链。A 省 token 但模型可能缺背景，B 更贴近"AI 理解你在问哪"但成本高。倾向 A 起步、B 作为设置项，待确认。

  决议（2026-10-02）：按倾向方案执行——默认 A（仅被选片段 + 用户问题），B（完整对话链）作为设置项提供。
- OQ-3: 删除对话是否提供回收站（软删除，可恢复）？倾向 v1 硬删除 + 二次确认，回收站进 backlog，待确认。

  决议（2026-10-02）：按倾向方案执行——v1 硬删除 + 二次确认（FR-11），回收站进 backlog。
- OQ-4: 并列对照面板的最大平铺栏数定为 3 是否合适（FR-15）？在 1080p 与 2K 屏幕上可能需要不同默认值，待实际 UI 走查确认。

  决议（2026-10-02）：按倾向方案执行——默认 3 栏（FR-15），待 UI 走查时在实际屏幕上复核。
- OQ-5: 对话标题自动生成用本地截取首句还是首次提问后额外调一次模型生成？成本同 OQ-1，倾向本地截取，待确认。

  决议（2026-10-02）：与 OQ-1 合并为用户设置项，默认本地截取首句。已落入 FR-16。
- OQ-6: 树状侧栏与链路图并存（侧栏常驻 + 链路图为可切换视图）是否符合预期？备选是二者互斥切换。倾向并存，待确认。

  决议（2026-10-02）：按倾向方案执行——侧栏常驻，链路图作为可切换视图（FR-7）。
