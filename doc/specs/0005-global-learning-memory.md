# Spec 0005: 全局学习记忆入口

**Status:** `accepted`
**Created:** `2026-10-20`
**Owner:** `产品所有者（本人）`

## Context

Deriva 已有树状对话、截图提问、资料面板与本地 SQLite 存储，但模型上下文只覆盖当前主对话及其祖先链。学生开启新对话后必须重新说明已学内容、偏好和过去做过的题目，Deriva 无法主动连接跨天、跨课程的学习经历。

本功能在 v3 第二阶段增加一个全局学习记忆入口，让 Deriva 从经过授权的本地学习记录中按需检索证据，并结合可修正画像继续教学。若只注入全部历史，会失控地增加成本与噪声；若只维护自动摘要，则无法解释、纠正或判断信息过期。因此本规格固定“证据层 + 画像层”的边界，并要求精度优先于召回数量。

本功能同时规定关系层边界：Deriva 可以记得学生经历、自然表达和适度鼓励，但不创建朋友人格、不模拟真人情感、不为了顺从认可错误答案。

术语沿用 CONTEXT.md：全局学习记忆入口、记忆篇章、关系层、知识画像、主对话、子对话、学习会话。

## User Scenarios

- **Scenario 1：跨对话关联学习经历**
  - Given 学生在过去的主对话中做过一道结构相似的算法题，并留下了题目、思路和薄弱点证据
  - When 学生在全局学习记忆入口询问一道新题
  - Then Deriva 只检索相关证据，指出相似与不同之处，附上旧对话来源，并正常给出新题教学；不得声称没有来源支持的过去经历

- **Scenario 2：按学生画像调整教学**
  - Given 学生的全局画像记录其为大一本科生，数学分析已学到极限但尚未掌握积分，算法画像记录其已掌握二分与递归
  - When 学生在算法问题中需要前置知识
  - Then Deriva 使用算法领域画像，不从数学画像推断算法熟练度；所需前置未掌握时先解释该前置

- **Scenario 3：没有足够相关记忆**
  - Given 历史记录中没有足够相关的证据
  - When 学生提出新问题
  - Then Deriva 明确表示没有找到足够相关的历史，按普通教学回答；不把弱相关或不相关旧对话包装成“你以前学过”

- **Scenario 4：查看并纠正画像**
  - Given 记忆中心有一条“已掌握矩阵乘法”的候选画像，来源为一次偶然答对
  - When 学生认为该画像不准确并修改或停用
  - Then 画像立即停止参与后续回答，旧候选与来源保留为过期记录，下一次请求不再注入旧结论

- **Scenario 5：退出全局记忆**
  - Given 某段主对话包含学生不希望进入全局记忆的私人内容
  - When 学生关闭该对话的“用于全局记忆”
  - Then 后续全局检索不再返回该对话或其附件，已派生的高风险画像失效或转为不可用候选；原始对话仍可在科目树中查看

- **Scenario 6：彻底删除来源**
  - Given 一条有效画像来自某段对话
  - When 学生删除该来源对话并确认删除
  - Then 对话、消息、附件和派生画像在同一次事务中失效或删除；后续请求与记忆中心不再引用失效来源

- **Scenario 7：关系层回应**
  - Given 学生因反复做错而表达挫败，同时认为自己已经掌握某个错误方法
  - When 学生要求 Deriva 直接认可该错误方法
  - Then Deriva 适度承认挫败和目标，不讨好地认可错误，清楚指出问题并给出下一步可执行帮助；不声称“只有我理解你”或模拟真人情感

- **Scenario 8：开启新篇章**
  - Given 全局学习记忆入口已有连续聊天内容
  - When 学生开启新的记忆篇章
  - Then 新篇章开始连续聊天，旧篇章与旧消息不删除且仍可作为记忆证据；全局入口不进入科目树

## Requirements

### Functional

- FR-1: Deriva 提供独立的全局学习记忆入口。该入口以单一连续聊天流呈现，支持用户主动开启记忆篇章，不进入科目树，不产生主对话或子对话节点。
- FR-2: 记忆篇章只负责划分全局入口的连续聊天区段。开启新篇章不得删除旧篇章、旧消息或旧证据。
- FR-3: 学习记录默认进入本地全局记忆索引，包括主对话、子对话、学习会话、全局入口消息与记忆篇章；用户可对任一段对话或篇章关闭“用于全局记忆”。
- FR-4: 持久记忆必须分为证据层与画像层。证据层保存原始消息、附件、来源关系与可用状态；画像层保存全局基础信息及科目/领域分画像，并为每条有效画像记录来源与置信状态。
- FR-5: 全局学习记忆入口不得把全部历史直接注入模型。每次回答只检索与当前问题相关的证据片段和当前有效画像，检索精度优先于召回数量。
- FR-6: 当相关证据低于系统定义的精度门槛时，Deriva 必须明确表示没有找到足够相关的历史，并允许用户主动扩大搜索范围；不得编造记忆、模糊来源或把弱相关记录表述为确定经历。
- FR-7: 每次使用旧学习经历形成实质结论时，回答必须提供可展开的来源引用，至少包含来源类型、科目或篇章标识、时间与原始消息入口。
- FR-8: 知识画像采用“全局基础信息 + 科目/领域分画像”。全局层可保存年级、学习目标、表达偏好和时间偏好；科目/领域层分别保存已掌握、未掌握、薄弱点、最近进度与证据。不得跨领域自动推断掌握度。
- FR-9: 用户明确说“请记住”“我已经学过 X”或纠正某条画像时，系统立即记录并生效；Deriva 自行推断的掌握度、能力或性格信息先形成候选，高风险画像在用户确认后才成为长期有效画像。
- FR-10: 画像更新在自然边界批量执行，包括对话结束、学习会话结束或用户显式请求。不得在每次流式回答结束后额外调用总结模型。
- FR-11: 画像冲突按“用户明确纠正 > 近期直接学习证据 > 旧推断”处理。单次表现只能形成候选更新；被替换的画像标记为过期，不得静默删除来源。
- FR-12: Deriva 提供记忆中心。用户可查看当前全局信息、分领域画像、候选、过期画像、来源、置信状态、最后更新时间，并执行确认、纠正、停用和删除。
- FR-13: 删除一条画像时默认只停用该画像并禁止继续参与回答，同时提供“同时删除来源”的明确选项。删除来源对话必须使用现有删除确认并级联清理相关消息、附件、记忆证据和派生画像。
- FR-14: 记忆呈现遵循分级规则：与学习问题直接相关的学习历史可以主动提起；表达偏好通常静默应用，仅在变化或冲突时说明；私人或情绪信息不得主动翻出，只有学生当前主动谈到或明确要求回忆时才可呈现。
- FR-15: 所有记忆结论必须区分用户明确陈述、原始证据和模型推断。用户修正优先于近期直接证据，近期直接证据优先于旧推断。
- FR-16: 全局学习记忆入口回答使用现有聊天、附件、流式输出、取消、错误处理与本地持久化管线，不另造模型客户端或对话存储。
- FR-17: Deriva 保持单一身份与关系层。回答可以自然、鼓励并识别挫败，但教学诚实和纠错始终高于顺从；不得创建朋友模式、第二人格、真人情感声明、排他关系或依赖性表达。
- FR-18: 全局学习记忆入口自己的消息和篇章进入同一记忆体系，但必须遵守 FR-3、FR-14 的退出与呈现规则。

### Non-functional

- NFR-1: 证据、画像、检索元数据、用户控制状态和来源关系保存在本地 SQLite；不接外部数据库，不把完整记忆库或画像同步到外部服务。为完成当前回答而发送给模型的内容继续遵守 API 请求与 token 预算；若采用远程 embedding，必须先通过 OQ-2 明确其内容范围与隐私影响。
- NFR-2: API Key 继续使用现有安全存储；记忆内容、检索查询、附件内容和画像不得写入普通日志或诊断上报。
- NFR-3: 关闭对话记忆、停用画像、删除来源与派生画像清理必须具有事务一致性。操作完成后的后续模型请求不得继续使用已停用或已删除内容。
- NFR-4: 检索与画像组装必须有明确的 token 预算和上下文裁剪规则；不得因历史增长导致每次请求无界增长。
- NFR-5: 在真实历史规模下测量记忆检索对首 token 延迟的影响，并在 `/ad-ground` 后记录预算门槛；未达标时降级为更小的检索集合，不阻塞普通对话。
- NFR-6: 检索、索引或画像构建失败时，全局入口和普通对话仍可继续以当前对话上下文回答，并显示可理解的降级状态。
- NFR-7: 记忆中心与来源引用支持键盘、光标和触控操作；关键操作热区不小于 44px，删除和停用操作必须可通过文字区分。
- NFR-8: 数据库迁移、索引重建或画像失效不得阻塞应用启动；失败时保留原始对话，禁止返回可能错误关联的旧索引。
- NFR-9: 任何性能或质量评估不得只依赖模型自评；至少包含可复现的本地请求快照、SQLite 查询结果与人工抽检。

## Success Criteria

- 用户能创建连续全局入口、开启新记忆篇章，并保留旧篇章作为可检索证据；全局入口不出现在科目树中。
- 对维护中的记忆黄金问题集，Deriva 只引用相关证据；所有“你以前学过/做过/说过”结论都能一跳打开来源，错误记忆为零。
- 没有足够相关证据时，Deriva 在普通问题中明确降级，不编造历史联系；用户可主动扩大搜索。
- 画像按全局与科目/领域分开；测试集不得出现数学熟练度被自动迁移到算法或其他领域。
- 用户明确纠正或删除画像后，下一次本地请求快照不再包含旧有效画像；被替换画像仍可在记忆中心追溯。
- 关闭一段对话的全局记忆后，SQLite 检索与模型请求均不再返回该对话内容；原始对话在科目树中仍可用。
- 删除来源对话后，消息、附件、记忆证据与派生画像在事务中一致清理，重启后无失效引用。
- 关系层黄金对话中，Deriva 能提供适度情绪价值，同时不认可错误答案、不声称真人情感、不制造排他依赖。
- 检索失败、索引损坏或模型失败时，普通对话保持可用，并显示不会误导为“完整记忆已生效”的状态。

## Edge Cases

- 学生首次使用，没有任何历史对话、学习会话或画像。
- 历史记录很多，但当前问题只有弱相关证据，或不同来源互相矛盾。
- 学生最近才学会某个概念，与旧画像冲突；或一次偶然答对产生高风险候选。
- 用户明确纠正后，旧来源仍存在；画像必须过期，来源仍可追溯但不再影响回答。
- 来源对话正在流式生成、刚被删除、被关闭全局记忆或所在显示器/资料面板已关闭。
- 同一概念存在于多个科目，名称相同但教学含义不同。
- 截图、PDF、网页附件包含私人信息、登录态或不可检索内容。
- 全局入口正在生成回答时用户切换篇章、停用记忆或删除来源。
- 数据库迁移中断、索引损坏、embedding 服务不可用或本地模型缺失。
- 学生要求 Deriva“忘掉”一条画像，但没有明确是否也删除来源。
- 学生处于明显挫败或情绪表达中，同时提出错误结论；关系层不得牺牲教学诚实。
- 学生要求 Deriva 假装真人、只理解自己、成为唯一朋友或认可错误答案。
- 用户长时间未使用，旧偏好或学习目标可能已过期。

## Out of Scope

- 用全局入口替代主对话/子对话树，或允许从全局入口派生子对话。
- 将全部历史直接注入模型，或只保存一段模型生成的全局总结。
- friend 人格、朋友模式、真人情感模拟、排他陪伴、心理治疗或危机干预。
- 自动跨领域推断能力、性格诊断或未经确认的长期高风险画像。
- 云端记忆、跨设备同步、共享记忆或外部数据库。
- 自动删除证据来执行“忘记”；证据删除必须由用户明确选择。
- 模型、embedding 服务和存储技术的最终选型；由 `/ad-ground` 决定。
- 具体性能数值、画像字段全集、候选保留期和检索阈值；保留为开放问题，研究后写入实现任务。

## Open Questions

- **OQ-1：采用何种检索组合？**

  候选为 SQLite FTS、向量检索、混合检索或模型生成关键词后检索。必须比较中文与数学公式召回、隐私、打包依赖、成本和大历史规模性能。

- **OQ-2：embedding 由 DeepSeek API、其他远程服务还是本地模型生成？**

  需要先核实当前模型提供商的 embedding 能力与价格，并评估本地模型体积、性能与 Node/Electron 打包成本。

- **OQ-3：SQLite 中证据与画像的具体 schema 是什么？**

  至少需要来源、有效状态、候选状态、置信状态、领域、更新时间、派生关系和删除级联；具体字段由 `/ad-ground` 与迁移测试决定。

- **OQ-4：记忆数据是否需要整库或字段级静态加密？**

  需要建立 Windows 同账号、数据库复制、备份与崩溃转储的威胁模型，再决定是否引入 SQLCipher、safeStorage 字段加密或仅依赖操作系统账户权限。

- **OQ-5：精度、延迟和 token 预算阈值取多少？**

  需使用合成大历史集与首要用户真实规模数据测量后确定，不预置无依据数字。

- **OQ-6：来源引用默认显示多少条？**

  倾向默认 1–3 条折叠引用；学生展开后查看完整来源。需验证回答可读性与可追溯性。

- **OQ-7：候选画像的合并、过期和批量处理规则是什么？**

  需要定义重复候选合并、长期未确认候选降级、过期画像保留期限与删除策略。

- **OQ-8：记忆中心如何分词与分领域展示？**

  倾向按全局基础信息、学习目标、各科目/领域、表达偏好、候选和过期画像分组；最终交互在设计任务中验证。
