# Spec 0002: 屏幕感知与截图提问（Screen Capture Questions）

**Status:** `accepted`
**Created:** `2026-10-06`
**Owner:** `产品所有者（本人）`

## Context

学生在阅读教材、代码、网页、视频或做习题时，经常需要把当前屏幕上的公式、图表、证明排版、题目条件或视频画面交给 AI。v1 的树状对话解决了“回答结构”和“知识水平错位”，但用户仍要手工复述屏幕内容；复杂公式和视觉排版很难准确转写，AI 也看不到题目限定条件、箭头、标注与图像细节。

ADR-0002 已决定模型接入走 DeepSeek 官方 API，默认 `deepseek-flash`，其视觉能力让屏幕感知从技术研究降为工程实现；ADR-0004 已在 v1 预留附件字段、可插拔上下文 block 与 `capture` 主进程模块。本功能让 AI 与学生共享同一份显式选择的屏幕上下文，是 v3 学习会话、字幕总结和知识画像的前置能力。若本功能不交付，用户仍需在“截屏工具 + 图片上传 + 手工描述”之间切换，学习流中断问题只会被部分缓解。

术语沿用 CONTEXT.md，并使用 v2 草案建议新增的三个领域词：屏幕片段、屏幕区域、屏幕提问。

## User Scenarios

- **Scenario 1:** 截取窗口或显示器提问
  - Given 用户已配置 DeepSeek API Key，且正在阅读 PDF、网页或观看课程视频
  - When 用户在 Deriva 中选择“截图提问”，选择目标窗口或显示器，预览并确认截图后输入问题
  - Then 系统生成屏幕片段，发送问题与截图给模型，并把该轮屏幕提问保存到当前主对话或新建主对话中

- **Scenario 2:** 框选局部内容选中即问
  - Given 屏幕上有一个公式、定理名、题目步骤、图表或视频字幕段
  - When 用户用光标或触控框选对应屏幕区域，并选择“提问”
  - Then 系统生成该区域的屏幕片段预览，用户确认并输入问题后发送；模型同时收到截图、问题和当前对话上下文

- **Scenario 3:** 在当前对话中继续使用屏幕提问
  - Given 用户已经打开一个主对话或子对话
  - When 用户发起新的屏幕提问
  - Then 屏幕片段作为附件挂到新消息上，回答沿用现有流式输出、书签、树状侧栏、链路图与多面板规则

- **Scenario 4:** 回看历史屏幕提问
  - Given 用户过去进行过屏幕提问
  - When 用户重启应用并打开对应对话
  - Then 缩略图、提问、回答、所属对话、引用关系和附件来源完整恢复；若用户当时选择“保留原图”，原图可查看，否则明确显示只保留了缩略图

- **Scenario 5:** 取消、失败与隐私保护
  - Given 用户进入截图选择或区域框选流程
  - When 用户取消、预览后拒绝发送、目标窗口属于隐私排除项、系统拒绝捕获、磁盘写入失败或 API 请求失败
  - Then 应用不产生隐藏截图或未确认的屏幕内容；已发送的提问和流式部分按 SPEC-0001 的错误、取消与部分内容保存规则处理

## Requirements

### Functional

- FR-1: 用户可显式发起“截图提问”，从可选窗口或显示器中选择目标，并在发送前看到屏幕片段预览。
- FR-2: 用户先选择捕获来源（v2 为显示器；SPEC-0003 落地后增加 Deriva 资料面板），再在该来源的截图上用光标或触控框选局部区域；预览确认前不得向模型发送任何屏幕内容。v2 不承诺外部窗口内部框选，外部窗口先支持整幅捕获。
- FR-3: 屏幕片段可附着到当前主对话或子对话的新问题上；未打开对话时，用户可创建新主对话承载屏幕提问。
- FR-4: 屏幕提问与普通文本提问共用流式回答、错误状态、取消、部分内容保存、模型标识和教学系统提示词。
- FR-5: 屏幕片段默认保存缩略图；用户可在预览中选择“保留原图”，设置中可修改默认值，并明确提示原图会占用更多本地空间。
- FR-6: 屏幕提问消息的附件、缩略图、可选原图、消息、对话树关系和来源引用即时持久化；应用重启后完整恢复。
- FR-7: 用户可在设置中配置隐私排除项：至少支持按显示器或窗口标题排除；被排除的目标不得出现在可选列表中，若当前预览目标变为排除项，则阻止发送。
- FR-8: 屏幕提问产生的回答仍支持 v1 的选中开子对话；子对话保留其来源回答和关联屏幕片段的可回溯关系。
- FR-9: 预览界面提供重新截取、取消、缩略图/原图保存选项和发送控件；空问题或纯空白内容不可发送。
- FR-10: 当模型当前配置不支持视觉输入时，屏幕提问入口应给出可理解的阻止提示，不静默丢弃截图。

### Non-functional

- NFR-1: 屏幕片段与附件保存在本地用户数据目录，不进入仓库、日志或诊断信息；API Key 仍按 SPEC-0001 的 safeStorage 规则处理。
- NFR-2: 默认缩略图应控制本地磁盘占用；单张缩略图与可选原图的大小上限在实现中显式约束，超出时降级保存缩略图并提示。
- NFR-3: 截图预览从目标确认到可交互不超过 2 秒（普通笔记本、单显示器场景）；区域框选过程界面保持可响应。
- NFR-4: 屏幕提问不得破坏 SPEC-0001 的对话性能要求；含图片附件的历史消息滚动与切换不造成明显卡顿。
- NFR-5: 触控适配：区域框选、预览确认、取消和发送控件在 Windows 触屏设备上可用，点击热区不小于 44px。
- NFR-6: 隐私：任何屏幕内容必须经过用户显式选择与预览确认后才可保存或发送；无后台持续读取屏幕。

## Success Criteria

- 用户能分别完成一次窗口/显示器截图提问和一次局部区域选中即问，两次提问均能得到流式回答并保存。
- 发送前预览、重新截取、取消、默认缩略图与“保留原图”选项全部可用；取消后不留下未确认截图。
- 隐私排除项生效：被排除的显示器或窗口不可选、不可发送。
- 重启应用后，屏幕提问的缩略图、提问、回答、对话树和引用关系完整恢复；保留原图的消息可查看原图。
- 屏幕提问的回答继续遵守教学系统提示词，且不因加入截图上下文而绕过 SPEC-0001 的树状对话规则。
- 从发起截图到问题发送完成，首要用例在普通熟练操作下不超过 30 秒。

## Edge Cases

- 无可捕获窗口/显示器、目标窗口最小化、窗口在预览前关闭或移动到另一显示器。
- 多显示器、不同缩放比例、触控与鼠标混用时，区域框选坐标不得偏移到错误显示器。
- 截图过大、附件目录不可写、磁盘空间不足或缩略图生成失败。
- 用户在流式回答期间再次发起屏幕提问；两次请求与消息归属不得串线。
- 未配置 API Key、网络超时、鉴权失败、余额不足、限流或模型拒绝视觉输入。
- 用户切换模型后，历史屏幕提问保留原模型标识；新模型不支持视觉输入时按 FR-10 阻止。
- 用户删除带有屏幕附件的消息或对话时，附件清理规则与 SPEC-0001 的删除规则一致。

## Out of Scope

- 后台持续屏幕读取、定时自动截屏、窗口变化监听、全局 OCR 监听或学习会话时间线（v3）。
- 视频字幕提取、纪要模板总结、思维导图、自动出题、费曼模式、知识画像（v3）。
- 全高悬浮抽屉、快捷气泡、全局热键与内嵌分屏的完整交互（SPEC-0003）。
- 选择并控制其他软件窗口自动并排（SPEC-0004）或读取其他应用内部 DOM/无障碍树。
- 第二家视觉模型、本地 OCR 或双模型路由。
- 云同步、多设备、多用户和截图分享协作。

## Open Questions

### Amendment 2026-10-16 — 来源优先与双捕获后端

经产品所有者确认，区域选择的交互模型明确为“先选捕获来源，再选择整幅或局部框选”。这次调整不改变 SPEC-0002 的功能目标或痛点：用户仍然可以框选公式、定理、题目步骤和视频画面并提问，只是把“框选哪个画面”从隐含的全屏语义改成显式来源语义。

架构上将捕获后端拆为两类：外部窗口与显示器继续使用 `desktopCapturer`；Deriva 资料面板等内部来源使用 `webContents.capturePage`。来源描述（kind、displayId、窗口标题、面板 id）会同时服务于截图提问、隐私排除和 v3 学习会话的来源集合。完整理由见 ADR-0005。

- OQ-1: 区域选择采用全屏覆盖层框选、系统截图工具唤起，还是 Deriva 内嵌选区工具？

  决议（2026-10-06）：不在规格中预置技术形态；`/ad-ground` 阶段比较 Electron 可实现性与触控体验，选择满足 FR-2/NFR-5 的方案。
- OQ-2: 原图与缩略图的尺寸/体积阈值定为多少？

  决议（2026-10-06）：`/ad-ground` 阶段结合 `deepseek-flash` 输入限制、普通 2K/4K 屏幕与学生设备磁盘占用给出实现参数，规格只要求默认缩略图与可选原图。
- OQ-3: 隐私排除是否支持应用名、URL 或内容关键词？

  决议（2026-10-06）：v2 最小方案支持显示器与窗口标题；更细粒度规则推迟到真实使用后评估。
