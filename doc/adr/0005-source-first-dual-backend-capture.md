# ADR-0005: 来源优先的双后端捕获架构

**Status:** `accepted`
**Date:** `2026-10-16`
**Deciders:** `产品所有者（本人）`

## Context

SPEC-0002 最初的区域选择实现把“框选屏幕”当成独立的全局操作：捕获所有显示器，隐藏 Deriva 自身窗口，再让用户在整屏截图上框选。这个实现满足“选中即问”的基本场景，但没有回答一个更基础的产品问题：用户要截取的究竟是哪一个学习材料来源。

SPEC-0003 要求 Deriva 内嵌资料面板 + AI 对话面板的分屏学习场景，并明确分屏资料面板中的公式、代码或网页内容也应能发起截图提问。当前实现无法满足这一点：`desktopCapturer` 捕获前会隐藏 Deriva 自身窗口，来源列表也会过滤 Deriva 窗口，因此 Deriva 内部资料面板在桌面捕获路径上不可见。继续把“整屏”当作唯一区域选择入口，还会让 v3 学习会话的录制范围难以定义。

## Decision

We will 把截图提问改为**来源优先**，并在 capture 模块中引入两类后端：

1. **来源优先**：用户先选择捕获来源（显示器、外部窗口，未来含 Deriva 资料面板），再决定整幅捕获或在该来源截图上框选局部。选区坐标始终相对所选来源的图像，不跨来源。
2. **外部来源后端**：显示器与外部窗口继续使用 Electron `desktopCapturer`；捕获时隐藏 Deriva 自身窗口，窗口源不可用时沿用名称回退与重试。
3. **内部来源后端**：Deriva 资料面板等内部内容使用 `webContents.capturePage` / `WebContentsView.capturePage`。内部来源不隐藏 Deriva，不依赖桌面捕获权限，也不过滤自身窗口。
4. **统一来源描述**：capture 模块输出稳定的来源描述（kind、displayId、窗口标题、面板 id、backend），供截图提问、隐私排除与 v3 学习会话复用。
5. **渐进交付**：v2（SPEC-0002）先实现显示器来源的整幅与局部捕获；外部窗口先支持整幅捕获；Deriva 资料面板的内部来源由 SPEC-0003 的独立任务实现。

## Consequences

- 正面：截图交互的语义从“截取屏幕”变成“截取我指定的学习来源”，与用户心智一致；SPEC-0003 的分屏资料面板从一开始就有正确的捕获路径；v3 学习会话可以按用户选择的来源集合录制，而不是默认录制整个桌面。
- 正面：隐私排除、附件、预览确认、树状对话和教学提示词可以复用同一套来源描述和后端接口。
- 负面：来源模型与捕获后端增加一层抽象；外部窗口内部框选在 v2 仍不承诺，用户若需要局部捕获，应选择显示器来源。
- 中性：当前已实现的整屏覆盖层不会被丢弃，它成为“显示器来源的局部捕获”后端；未来内部来源会复用相同的选区与预览确认流程。

## Alternatives Considered

* 维持“框选屏幕”作为独立全局操作 — 无法捕获 Deriva 分屏资料面板，且把“来源”隐含在全屏截图中，v3 仍需返工。
* 只用 `desktopCapturer` 捕获 Deriva 自身窗口 — 捕获前隐藏自身窗口是防自拍的必要行为，且当前来源列表已过滤自身窗口；不能可靠捕获 Deriva 内部内容。
* 用 DOM 截图替代内部渲染捕获 — 跨域网页、PDF、视频和复杂布局不可靠，不能作为统一后端。
* v2 一次性实现所有来源内部捕获 — 会把 SPEC-0003 的分屏依赖提前带入 SPEC-0002；来源优先的接口在此刻固定，内部后端按 SPEC-0003 独立交付。
