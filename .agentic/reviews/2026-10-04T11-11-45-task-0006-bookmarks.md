## Resolution log (post-review, same turn)

- Standards Concern 1 (bookmark generation delayed the terminal event) — fixed: the service now emits
  `done` immediately after persisting the answer, and only then awaits bookmark generation. The request
  still counts as active until both finish, so the composer unlocks as soon as the answer is complete
  while the bookmark lands a moment later (or falls back to a local summary on failure).
- Spec Concern 1 (FR-16 warning hidden inside the option label) — fixed: selecting 模型生成摘要 now
  renders a permanent hint under the select explaining the extra call, the added token cost and the
  local fallback.
- Spec Concern 2 (bookmarks exist only for completed answers) — resolved as a documented product
  decision: an aborted or failed half-answer does not earn a navigation anchor, because its summary
  would describe text the student never finished reading. Recorded in the Task 0006 Notes so it is a
  stated choice rather than an oversight; the user can reverse it by asking for bookmarks on abort.
- Standards Notes 2–4 — recorded: bookmark positions are computed at creation time and would need
  renumbering if single-message deletion ever lands; the rail does not scroll-spy (FR-6 asks only for
  click-to-jump); the fixed 156px rail width needs a narrow-column decision in Task 0007.

Post-fix verification: 129 tests pass, `npm run typecheck` clean, `npm run build` produces all three
bundles.
