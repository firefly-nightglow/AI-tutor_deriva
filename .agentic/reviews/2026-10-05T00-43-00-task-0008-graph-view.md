## Resolution log (post-review, same turn)

- Standards Concern 1 (the toggle could claim "对话视图" while the pane list was actually on screen) —
  fixed by deriving one `showingGraph = view === 'graph' && graphRootId !== null` and using it for both
  the label and the rendered surface, so a deleted root can no longer desynchronise them.
- Spec Concern 1 (NFR-4 had no admissible evidence) — retired with a measurement in the real renderer:
  a temporary dev self-check seeded a 300-node (4-ary) tree through the app's own IPC, switched to the
  graph view and polled the DOM until every node and edge was mounted. Result:
  `{"nodes":300,"edges":299,"elapsedMs":218}` from the click to a fully rendered graph, measured in dev
  mode — the pessimistic case per React's own guidance, so the 500 ms budget holds with margin. The
  temporary code was removed afterwards (grep-verified) and the suite re-run.
- Spec Concern 1, second half (lazy loading beyond the budget) — implemented as an opt-in render cap:
  `limitConversationGraph(graph, 300)` hands React Flow only the first 300 nodes in depth-first order and
  drops edges whose endpoints fall outside that prefix; the graph shows "树较大，已显示前 300 个节点，还有 N
  个未显示" with a 全部显示 control. This is stated precisely rather than oversold: dagre still lays out
  the whole subtree (the cheap part); what the cap avoids is mounting thousands of nodes, edges and
  handles at once.
- Standards Notes 2–5 — recorded: route-level lazy loading of deep subtrees is not implemented (the cap
  covers the mount cost); React Flow's attribution badge is left in place because hiding it is a paid
  feature; `nodesDraggable={false}` means students cannot rearrange the map (a deliberate v1 choice);
  the jsdom test asserts node count only, because React Flow draws edges into an SVG sized from real
  layout.

Post-fix verification: 155 tests pass, `npm run typecheck` clean, `npm run build` clean.
