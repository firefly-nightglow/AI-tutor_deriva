## Resolution log

- Standards Concern 1 — the bookmark rail preference was global in localStorage but held in each pane's
  own state, so collapsing in one pane left the others expanded until remount. Fixed by lifting the
  state to App (with a stable `onToggleRail`) and passing it down; the presentation test now renders the
  collapsed rail directly, and a unit test covers the storage round-trip.
- Drag smoothness (reported live as "a bit laggy") — two changes, both preserving behaviour:
  `ConversationPane` is wrapped in `memo` and App now hands it id-addressed `useCallback` handlers, so a
  drag re-renders the thin pane wrappers instead of re-typesetting KaTeX in every pane; and pointer
  moves are coalesced with `requestAnimationFrame`, so at most one state update per frame instead of one
  per pointer event. Cancelling a pending frame on pointerup keeps the last position.
- Standards Notes — recorded, no action here: pane widths are deliberately session-only; `branchRanges`
  marks the first occurrence of a repeated passage; a mid-drag re-render re-applies the committed width
  (safe because every frame commits, and it is why direct DOM writes were avoided); touch dragging rests
  on Pointer Events + `touch-action: none` and has not been exercised on a touch device.

Post-fix verification: 147 tests pass, typecheck and build clean, dev smoke check healthy.
