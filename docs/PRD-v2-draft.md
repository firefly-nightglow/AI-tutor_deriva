# PRD Draft - Deriva v2 屏幕感知

**Status:** `draft`
**Created:** `2026-10-06`
**Base documents:** `doc/product/PRD.md`、`CONTEXT.md`、ADR-0001、ADR-0002、ADR-0003、ADR-0004、ADR-0005、ADR-0006
**Purpose:** 汇总 v1 封版后，v2 需要新增或修改的产品内容；确认后再按 `/ad-spec` 编写功能规格。

## 对现有 PRD 的建议修改

1. 将 `doc/product/PRD.md` 的 `Updated` 更新到 v2 草案确认日期，并把 v1 验收指标标注为已完成。
2. 在 `Product` 中补充“屏幕内容共享”一句：Deriva 不只是把 AI 放在桌面上，还让用户把正在阅读或观看的屏幕内容作为提问上下文直接交给 AI。
3. 在 `Goals` 中补充：
   - 用户看到教材、题目或视频中的陌生内容时，可以显式截取对应屏幕区域并提问，不离开当前学习窗口。
   - AI 看到的截图与提问一起进入对话链，回答可回溯到具体截图或屏幕片段，而不是脱离上下文的泛泛解释。
4. 在 `Roadmap` 中把 `Next tier - 屏幕感知（截图提问、选中即问，基于 deepseek-flash 视觉能力）`展开为：
   - **v2 - 截图提问**：用户显式选择当前屏幕中的一个窗口、显示器或区域，确认截图后进入提问流程。
   - **v2 - 选中即问**：用户选取屏幕上的一个更小区域（公式、定理、题目步骤、视频字幕段）后直接提问；回答可继续沉淀为主对话或子对话。
   - **v2 - 屏幕上下文沉淀**：每次显式截图与问答、附件、来源消息和树状对话关系一并保存，支持后续回看。
5. 保持 v2 不承诺“开始学习后持续读取屏幕”或“暂停学习”。“暂停/结束学习”仍属于 v3 的学习会话范围。

## Product

Deriva v2 在 v1 的树状对话基础上加入显式屏幕感知：当学生面对教材、题目或视频中的陌生内容时，可以截取屏幕上的具体内容并立刻提问；截图作为消息附件与上下文一起发送给 `deepseek-flash`，让 AI 看到用户正在看什么，而不是靠学生复述。

v2 的产品边界是“用户主动选择并确认要共享的屏幕内容”，不是后台持续监控屏幕。

## Target User

沿用现有 PRD：首要用户是产品所有者本人，目标用户是大学本科生，特别是阅读教材、公开课与高质量课外资料时经常遇到陌生定理、公式、题目步骤或视频内容的学生。

v2 特别覆盖这些使用情境：

- 阅读 PDF、网页或电子书时遇到陌生公式、定理或证明步骤。
- 观看课程视频时想针对当前画面、字幕段或板书提问。
- 做习题时需要展示题干、选项、图表或自己的推导截图，而不是手工转写。

## Problem

v1 已解决“对话逻辑结构丢失”和“回答水平错位”的主要问题，但用户仍要手工把屏幕内容复述给 AI：公式、图表、证明排版和视频画面很难完整转写，转写过程本身会引入遗漏和误解。AI 与学生仍然没有共享同一份视觉上下文，尤其会表现为：

1. **转写成本高**：复杂公式、矩阵、图形、字幕和截图布局很难用文本准确表达。
2. **上下文仍可能错位**：学生以为自己描述清楚了，AI 实际上没有看到排版、箭头、标注或题目限定条件。
3. **视频场景无法停顿整理**：遇到一闪而过的板书或字幕时，用户需要暂停、截屏、切到 AI 再贴图。
4. **追问来源不可回看**：如果截图没有与对话持久关联，后续复习时很难知道 AI 当时看到的是哪一屏。

## Goals

- 用户能通过一次显式操作截取当前学习资料，并基于截图发起提问。
- 用户能截取较小的屏幕区域并直接提问，尤其是公式、定理、题目步骤、图表和视频字幕。
- 用户能在 Deriva 内嵌资料面板中一边阅读文献、代码、网页或视频，一边查看和追问 AI 输出；普通窗口左右分屏，悬浮抽屉上下堆叠。
- 用户能选择一个正在运行的外部应用（如 VSCode、Chrome、B 站客户端），让它与悬浮抽屉自动并排、共享工作区并调整边界；该能力由 SPEC-0004 单独规定，并以 Windows 窗口控制 spike 为门槛。
- 截图提问采用来源优先：用户先选择要截取的显示器、外部窗口或 Deriva 资料面板，再决定整幅捕获或局部框选；外部来源使用 `desktopCapturer`，Deriva 内部来源使用内部渲染捕获。
- 用户能通过全高悬浮抽屉、圆形快捷气泡、常驻托盘与全局热键，在学习资料旁随手唤起 Deriva。
- 截图、用户问题和 AI 回答进入同一对话链，并在本地长期保存、可回看。
- 屏幕感知回答继续遵守教学系统提示词：从学生已掌握知识出发，不因看到截图而直接跳到超水平结论。
- v2 复用 v1 的树状对话、上下文管线和本地附件机制，不为屏幕感知另建一套对话系统。

## Non-goals

- 持续后台录屏、定时自动读取屏幕、全局 OCR 监听或隐私不可控的屏幕共享。
- “开始学习 / 暂停学习 / 结束学习”的状态机及其总结、思维导图、出题检验；这些属于 v3。
- 覆盖任意软件内部的免截图 DOM/无障碍树抓取；v2 使用截图和视觉模型作为统一方案。
- 在 v2 中引入第二家视觉模型或本地 OCR；本地 OCR 只保留为后续降本评估方向。
- 修改 v1 的树状对话核心交互或迁移既有对话数据。

## 建议新增或更新的领域词

以下词汇建议进入 `CONTEXT.md`，在 v2 功能规格中统一使用：

### 屏幕片段 (Screen Capture)

**Definition:** 用户通过 Deriva 显式选择并确认的一次屏幕截图，可来自窗口、整个显示器或用户框选区域；作为附件进入提问上下文和本地对话存档。

_Avoid_: 截图消息、屏幕片段文件 — 前者是实现层消息类型，后者偏文件形态。

### 屏幕区域 (Screen Region)

**Definition:** 用户用光标或触控在屏幕上框选出的局部矩形区域，用于选中即问；屏幕区域会产生一个屏幕片段。

### 屏幕提问 (Screen Question)

**Definition:** 以屏幕片段为主要上下文发起的提问，可以落在现有主对话内，也可以开启子对话；与普通文本提问共用树状对话与流式回答机制。

## User Scenarios

- **Scenario 1：截取窗口或显示器提问**
  - Given 用户正在阅读 PDF、网页或观看视频
  - When 用户在 Deriva 中选择“截图提问”，选择目标窗口或显示器并确认
  - Then 应用生成屏幕片段预览，用户填写问题后发送；截图和问题一起进入当前主对话或新建主对话

- **Scenario 2：框选局部内容选中即问**
  - Given 屏幕上有一个公式、定理名、题目步骤或视频字幕段
  - When 用户框选该区域并选择“提问”
  - Then 应用生成该区域的屏幕片段，用户输入问题后发送；模型同时收到截图、问题和当前对话上下文

- **Scenario 3：基于已有回答继续屏幕追问**
  - Given 用户已经基于屏幕片段得到一段 AI 回答
  - When 用户选中回答中的推导步骤并开子对话
  - Then 子对话沿用 v1 树状对话规则，保留原屏幕片段来源，便于回看当时看到的内容

- **Scenario 4：取消或失败**
  - Given 用户进入截图选择流程但尚未发送问题
  - When 用户取消、关闭预览、系统拒绝捕获或网络/API 失败
  - Then 应用不产生不完整对话；已保存的提问与已有部分内容按 v1 错误与取消规则处理

- **Scenario 5：窗口级分屏学习**
  - Given 用户正在 Deriva 中阅读文献、代码、网页或视频，同时查看 AI 输出
  - When 用户在普通窗口或悬浮抽屉中打开资料面板
  - Then 普通窗口左右分屏、悬浮抽屉上下堆叠，用户可独立滚动两侧并继续树状问答

## Success Metrics

- **提问闭环时间**：从看到陌生屏幕内容到问题发送完成，普通熟练操作不超过 30 秒，测量来源为首要用例的实际操作走查。
- **视觉上下文利用率**：v2 上线后，涉及公式、图表或视频画面的提问中，使用屏幕提问而不是手工转写的比例超过 50%，测量来源为本地对话记录中的附件消息占比。
- **上下文错位减少**：首要用例抽检中，AI 因“没有看清题目条件、排版或图表”而答偏的比例低于 10%，测量来源为 v2 黄金对话集。
- **回答质量不回落**：引入截图上下文后，“从底层知识作答”达标率继续保持现有 PRD 目标（首要用户主观判定超过 80%）。
- **本地可追溯性**：每条屏幕提问的截图、提问、回答、所属对话和来源关系重启后可完整恢复，测量来源为 v2 功能验收。

## Constraints

- 沿用 ADR-0001：Windows 桌面应用，Electron + React + TypeScript，SQLite 本地存储。
- 沿用 ADR-0002：模型接入仅走用户自备 DeepSeek API Key，默认 `deepseek-flash`，不嵌入网页版，不新增第二家视觉模型。
- 沿用 ADR-0004：屏幕感知落入 `src/main/capture` 模块；截图作为消息附件与可插拔上下文 block 注入，不重写聊天核心。
- 沿用 ADR-0005：截图来源先选、后端分离；v3 学习会话按用户选择的来源集合记录，不默认录制整个桌面。
- 截图和附件保存在本地用户数据目录，不进入仓库、日志或诊断信息。
- v2 的屏幕捕获必须由用户显式触发并确认；不做持续读取屏幕。
- 触屏和鼠标均可完成区域选择，关键控件满足现有 44px 触控热区要求。

## Roadmap 调整

- **v1.0.0 已封版**：树状对话、API 对话、本地 SQLite 和教学提示词 v0.1 已完成；窗口级悬浮窗形态未随 v1.0.0 交付，后续需单独规格决定是否在 v2 合并实现。
- **v2**：显式屏幕感知（窗口/显示器截图提问、局部区域选中即问、截图上下文沉淀），基于 `deepseek-flash` 视觉能力；同时交付全高悬浮抽屉、快捷气泡、常驻托盘、Deriva 内嵌资料面板，以及以 spike 为门槛的外部应用并排（SPEC-0004）。
- **v3**：学习会话（开始/暂停/结束学习、后台持续屏幕读取时间线、纪要模板总结、思维导图、出题检验、知识画像）。学习会话保留屏幕内容与音频转写两条独立来源流；具体实现顺序、采样方式与本地/云端方案到 v3 规划时再定。

## Open Questions

- **OQ-v2-1：v2 是否同时实现屏幕边缘吸附悬浮窗？**

  决议（2026-10-06，2026-10-18 修订）：v2 实现完整悬浮窗，归入 SPEC-0003；形态为全高抽屉 + 快捷气泡 + 常驻托盘。
- **OQ-v2-2：区域选择的交互模型**

  决议（2026-10-06）：在 `/ad-ground` 阶段比较 Electron 可实现性与触控体验，规格只约束结果与可访问性，不预置技术形态。
- **OQ-v2-3：截图默认保存策略**

  决议（2026-10-06）：默认保存缩略图并提供“保留原图”选项。
- **OQ-v2-4：隐私排除规则**

  决议（2026-10-06）：提供隐私排除规则；v2 最小方案包含发送前预览与取消，并在设置中提供排除显示器/窗口的能力。
- **OQ-v2-5：视频场景是否抽取字幕文本**

  决议（2026-10-06）：v2 只支持“截取当前视频画面提问”，字幕提取和总结留给 v3。
- **OQ-v2-6：双模型路由是否开始评估**

  决议（2026-10-06）：不预置双模型路由；v2 文本与截图都走 `deepseek-flash`，上线后再按回答质量与成本评估。
- **OQ-v2-7：窗口级分屏的实现边界**

  决议（2026-10-18）：内嵌资料面板归入 SPEC-0003；外部应用并排提升为 v2 的独立 SPEC-0004，以 Windows 窗口控制 spike 为门槛。两者互补：内嵌面板承载网页、PDF 与视频网站，外部并排承载 VSCode、带扩展浏览器、桌面客户端等原生应用。
- **OQ-v2-8：后台持续屏幕读取的范围**

  决议（2026-10-06）：后台持续屏幕读取与学习会话时间线归入 v3，v2 不做持续读取。
- **OQ-v2-9：悬浮抽屉形态与 v3 来源流的关系**

  决议（2026-10-18）：悬浮模式采用全高抽屉 + 快捷气泡 + 常驻托盘；v3 学习会话保留屏幕与音频两条独立来源流，可复用外部并排保存的稳定窗口/进程标识，但不假设并排始终生效，也不在本阶段绑定采集实现。

## Proposed Specs

确认本草案后，v2 拆成三份功能规格：

1. `SPEC-0002: 屏幕感知与截图提问`——窗口/显示器/区域捕获、预览确认、截图附件、上下文注入、错误与取消、触控适配。
2. `SPEC-0003: 悬浮窗、快捷入口与窗口级分屏`——全高悬浮抽屉、圆形气泡、常驻托盘、全局热键、单实例恢复，以及 Deriva 内嵌资料面板的分屏学习场景。
3. `SPEC-0004: 外部应用并排`——选择一个外部应用、与抽屉共享工作区、调整边界、暂停/还原与 Windows 原生窗口控制降级。
